# Press Start native fallback ownership

After the Linux packaging fix (#446), missing or rejected title resources can still occur. The HD gradient is drawn above the native picture. Previously it took BG0 unconditionally whenever the title/HD option was enabled, even when Press Start's replacement parts were rejected and its native words remained.

The PPU now gates that handover after the real HD queue pass. It checks the actual Press Start tile identities (including EU languages) and requires every active visible-type part to have an accepted sMainHdPart. This includes decode/upload, transform and queue rejection through the existing QueueHdPart result; file presence alone grants no ownership. Disabled, invalid and OBJ-window slots do not represent visible words. A phase without active words, or with OBJ disabled, retains the prior HD bar behavior so all-good entry/blink phases do not switch gradients. No persistent readiness cache, art bytes, original GBA rendering rules or timing are changed.

## Verified scope

- Execute the extracted real QueueMainHdParts and TitleBarLine, not a second implementation: 56 C/Clang checks across EU/US/JP builds. Missing/corrupt-id0, resource-known-but-queue-rejected, partial acceptance and next-frame rejection failed before the fix and pass afterward. Full acceptance, disabled/no-word/OBJ-off phases, unrelated rejected sprites, leaving the title and Original/GBA controls pass. The first harness attempt lacked stubs; another corrected its own fresh BG-row setup between frames. Neither harness error is reported as a product failure.
- Private EU32 probes relink 357 existing Windows objects readonly, replacing only PPU plus an equal private loader control in both binaries. That control disables PE embedded lookup so real filesystem missing/rejected resources behave like Linux. It does not alter SDL or image bytes in the source tree. Tests use a real private EU cartridge copy.
- All-good entry/white fade/slide/blink/menu sequence: 31 actual D3D11 frames and 31 SDL software frames are pixel-identical before/after. Three Original/GBA frames are also identical (65 positive control images total), using the existing menu frame-clock control.
- Negative with both selected Press Start frames and poster absent, matching the public Linux condition: the final T retains only32 black pixels before, versus256 after, exactly matching the original GBA T mask at frames600/660/720. The same six before/after outcomes hold with intentionally invalid private PNG headers. Delta is confined to the native bar strip (436,616)-(960,652) at960x720. Source assets remain unchanged.
- Missing only the words while the HD poster is present was an unsuitable visual negative: MainHdOver already preserved the native T there. Its recorded before/after T masks are equal; it is not counted as a reproduction of the clipping.
- Linux i386 and Linux64 x32-guest PPU-only compile/link pass against immutable cached objects, with ABI flags preserved. The Linux64 guest baseline is the worker's current248b3083 build, not the public ace4116 binary; its flags are compared against the real producer constructor, allowing only private source-root changes.
- Native Linux software VM: all12 bounded cases (32/64, full/missing/corrupt, before/after) exit0 with raw captures. Valid-resource captures are pixel-identical in each architecture. Both missing/corrupt cases restore the T from2 to16 black native-cell centres, exactly matching the original GBA reference, with zero accepted HD word records. Delta stays inside the bar strip. The actual64 host output is1280x720 (scale4.5, offset100,0), while32 is960x720 (scale4, offset0,40); native-cell-centre sampling avoids fractional-filter edge ambiguity. FALLBACK-LINUX-VERIFIED.json records the method, masks and exact bounds. QEMU is terminated and the exclusive lease released. No Linux GPU/physical Deck claim follows from SDL software captures.
